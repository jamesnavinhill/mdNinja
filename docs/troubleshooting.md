# Troubleshooting

Fast fixes for the failures you'll actually hit.

## Workbench won't start

| Symptom | Fix |
| :--- | :--- |
| `EADDRINUSE` on the port | Something already owns it: `npx @mdninja/cli -p 3001`, or kill the old process. |
| Page loads, file tree is empty | The target directory has no Markdown the scanner reads. Run `npx @mdninja/cli init` to scaffold a canon, or point `-d` at a repo that has one. |
| `mdninja build` in a foreign repo | `build` targets the mdNinja monorepo. Use it there; elsewhere use `dev` — the workbench works on any repo. |

## GitHub "Connect Account" does nothing

The OAuth popup needs a registered callback that matches your app's origin exactly, character for character:

1. `NEXT_PUBLIC_APP_URL` must equal the origin the OAuth App knows (apex domain, no trailing slash drift).
2. The OAuth App's **Authorization callback URL** must be `<that origin>/api/auth/callback/github`.
3. Local dev: register `http://localhost:3000/api/auth/callback/github` on the OAuth App, and keep `NEXT_PUBLIC_APP_URL` at its default while you test locally.

If the popup opens GitHub and returns an error page, the origin mismatch is the cause — the exchange is ephemeral, so there's no server log to dig through.

## Diagram renders blank

Mermaid measures text to size its canvas. In some headless/automated browser contexts that measurement comes back zero-width, and the gantt renders empty. It renders correctly in a normal desktop browser. If you see a blank diagram:

1. Confirm the fenced block says ```` ```mermaid ```` (a stray character in the fence breaks interception).
2. Validate the syntax against the [Mermaid Live Editor](https://mermaid.live) — the app surfaces the render error message in place of the SVG when the source is invalid.
3. Hard-refresh; a stale bundle from before a theme change occasionally shows a stale (or blank first) paint.

## Code blocks look "wrong" in light theme

Deliberate: fenced code stays dark in both modes so snippets read the same regardless of palette. The policy lives in `apps/web/src/styles/markdown.css` (`--code-block-bg`). Inline `code` follows the theme.

## Docs look stale on the hosted demo

The web bundle ships a build-time snapshot of the canon (`apps/web/src/lib/canon-data.json`, regenerated by `sync-canon` on every `npm run build`). A docs-only push needs a rebuild+deploy to show up on Vercel; the local workbench always reads the disk live.

## Desktop build fails

* `cargo` missing → install the Rust toolchain (`rustup`).
* Windows without WebView2 → the OS webview prerequisite; Tauri's build output tells you which one is missing.
* Port clash with a running `npm run dev` → `tauri dev` starts the web build on `:3000` via `beforeDevCommand`; stop the other one first.
